# 会议纪要导出

把企业空间会议助手（录音卡 / 手机录音）里当前账号上传的录音、转写和 AI 总结导出到本地，
整理成规范归档，并可上传企业知识库。

## 一句话安装

把下面这句发给 SpaceAgents：

> 帮我装「会议纪要导出」，地址是 github.com/kingkemander/meeting-recording-agent

装完**新建一个会话**，智能体下拉里选「会议纪要导出」。

## 它解决什么问题

- 录音在手机 / 录音卡上，电脑要看就要一条条下 → 一句话批量导出
- 转写和 AI 总结散在网页里 → 落成本地 Markdown 归档
- 会议内容要进知识库 → 归档后一键上传
- 登录态每台电脑都要重新弄 → 三条取证路径自动获取，缓存约 180 天

## 登录态怎么拿（不需要手工复制 Cookie）

| 路径 | 用户要做 | 说明 |
| --- | --- | --- |
| A 复用浏览器 | 最多在钥匙串弹窗点一次「允许」 | 本机 Chrome / Edge / Brave 登录过就自动解密复用 |
| B 内置浏览器 | 在右侧面板自己输一次账号密码 | 脚本从调试端口抓，全程不接触密码 |
| C 账号密码 | 在对话里给一次 | 需用户明确同意；密码只走 stdin，不落盘、不回显 |

用 **上传录音的那个账号** 取登录态。会议接口按 `scope=mine` 过滤。

## 命名规则

知识库没有改名接口（文档名 = 上传文件名），所以上传前必须命名：

```
MTG-2026-10-14 职称评审材料填报培训 · 手机录音 10-14 10-47.md
```

主题是读转写提炼出来的（8–20 字，说清跟谁谈什么），不是设备名。修改记录见 `CHANGELOG.md`。

## 产物

```
meeting-exports/<日期>-<标题>/
  recording.<ext>   原版录音
  transcript.md     带时间轴的转写
  summary.md        元信息 + AI 摘要 + 待办 + 关键词
  meeting-notes.md  合并稿（面向知识库）
```

## 依赖

Python 3.8+，仅标准库。私有化部署先设 `DEN_API_BASE`。

## 边界

只读本账号会议；不调用删除 / 修改 / 共享接口；不自动发布；不伪造空录音的转写与总结。
